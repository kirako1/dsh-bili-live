# dsh-bili-live · 直播总结

**让插件自己看直播，并总结直播内容。**

挂在你自己的 B站 账号上，安静地待在直播间里：读弹幕、听主播说话、看画面在做什么，离场时留一张笔记。
平时一句话不说，只有被叫到才接一句。

> 适用于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）桌面版 / Web 版。

---

## 它能做什么

| | 能力 | 说明 |
| --- | --- | --- |
| 👀 | **看弹幕** | 长连接接收弹幕，只读不发。守指定主播（行序即优先级），或按喜好关键词自动巡场。 |
| 👂 | **听声音** | 拉直播音频流切片，本机 faster-whisper 转写。**不花 token、不联网**。听到关键词会接话，也会写进笔记。 |
| 🖼 | **看画面** | 定时从视频流里抽一帧（PyAV 解码，不落临时视频），总结时把画面一起交给模型。 |
| ⭐ | **给主播打分** | 八维评分，权重自己调。看不满 60 秒不打分。 |
| 📝 | **写笔记** | 一场直播一张 txt：评分明细、发生了什么、大肥鱼的评价、最热闹的一分钟、弹幕摘录、主播原话。 |
| 📬 | **高分推送** | 分数过线时把这场推给指定的 B站 账号（B站 不允许发给自己，要填另一个 UID）。 |

## 一场直播的流程

```
进房（守名单或随机巡场）
   ↓
三路同时采：弹幕长连接 / 15 秒音频切片 / 每 2 分钟一张画面
   ↓
离场（主播下播、被更高优先级顶掉、看满巡场时长、你点了停止）
   ↓
算分 → 模型写笔记 → 过线推送 → 删掉这一场的切片与截图
```

## 随机巡场

关注名单留空（或关掉「启用关注名单」）时，插件自己挑台：

1. 没看过的、命中**喜好关键词**的房间优先
2. 没命中但也没看过的
3. 实在没得挑才回到最近看过的（记最近 12 间）

默认每间看 30 分钟就换；看不满 60 秒被切走的那一场不打分、不推送。

## 评分怎么算

八个维度，各自按「满分量级」做对数归一，再按权重加权，满分 10 分：

| 维度 | 默认权重 | 满分线 |
| --- | --- | --- |
| 弹幕密度 | 20% | 20 条/分 |
| 月投稿数 | 20% | 5 条/30 天 |
| 同接（真实在线人数） | 15% | 70 人 |
| 大航海 | 15% | 50 位 |
| 发言人数 | 10% | 20 人 |
| 付费人数 | 10% | 30 人 |
| 获赞率 | 5% | 2000 赞/稿 |
| 互动率 | 5% | 30 条/百人/分 |

权重在设置页自己填百分数，**不用凑满 100**（算分时按合计归一），填 0 就是完全不看那一项。

同接取的是 `getOnlineGoldRank` 返回的真实在线人数，不是页面上那个虚高几百倍的「人气值」。

```
==============================================
直播间：https://live.bilibili.com/00000
开播标题：今天随便聊聊
观看时段：20:01 ~ 21:20（1 小时 19 分）
弹幕：共 1234 条，89 人发言
语音：转写出 210 段主播说的话
同接峰值：76 人在看
评分：7.6/10（B 档 · 还行）
　同接 76（13.2 分） · 发言人数 30（14.8 分） · 弹幕 10（13.7 分） · 月投稿 50（20 分）
　付费 10（10 分） · 大航海 0（0 分） · 获赞率 507（5 分） · 互动率 13（2.4 分）
==============================================

【这场直播大概发生了什么】
（模型写的 100~180 字现场笔记）

【大肥鱼的评价】
（模型写的 60~120 字主观看法：值不值得看、什么路数）

【最热闹的一分钟】

【弹幕摘录】

```

模型不可用时不会整张空白，会退化成「本地统计版」（时长、条数、最热闹的一分钟、高频词）。

## 安装

```bash
# 从 GitHub
dsh plugin --profile desktop add github:你的用户名/dsh-bili-live

# 或从本地目录
dsh plugin --profile desktop add link:/绝对路径/bili-live
```

装完**重启 DSH**，侧边栏「设置 → 直播总结」就是它的设置页。

### 听声音需要本机 ASR 环境（可选）

语音转写用本机 Python + faster-whisper，两部分都要有：

```bash
# 1. 建 venv 并装依赖
python -m venv ~/.dsh/bili-live/.venv-asr
~/.dsh/bili-live/.venv-asr/Scripts/pip install faster-whisper

# 2. 下载模型（首次转写会自动下，也可手动预热）
#    默认 medium，约 1.5 GB；机器吃力可在设置页切 small
```

找不到 Python 时插件只是「听不到声音」，弹幕、画面、评分、笔记照常工作。
抽帧只需要 `av`（PyAV）与 `Pillow`：

```bash
~/.dsh/bili-live/.venv-asr/Scripts/pip install av Pillow
```

## 隐私

- **凭证只认自己扫的**：插件自带扫码登录，不借用其它插件的登录态；没扫码就显示「还没有登录」。凭证存在插件家目录 `~/.dsh/bili-live/credential.json`，每 10 分钟校验一次，过期自动掉线。
- **语音转写在本机跑**：音频不出本机，不花 token。只有「接一句话」和「写一张笔记」会调用模型。
- **不采集你的账号信息**：插件只读直播间的公开数据（房间信息、弹幕、音频流）。

## 成本

| 动作 | token |
| --- | --- |
| 听声音、抽画面 | **0**（本机计算） |
| 接一句话 | 约 800 |
| 写一张笔记 | 约 8k ~ 9.5k（含 3 张画面） |

一场 3 分钟的小直播约 9k token；长时间挂机时，也可以把「总结参考画面」关掉来省。

## 边界与注意事项

- **弹幕发送受 B站 风控约束**：需要登录 cookie 与 `buvid3`；冷却与每日上限是为了不刷屏被封，别调得太激进。
- **@ 识别是文本层面**：B站 弹幕里的 @ 不一定带结构化字段，按「文本里出现名字/别名」判断，可能偶尔误判。
- **部分直播间有发言等级限制**：发不出去时日志里有报错，插件照常观看，只是说不了话。
- **弹幕与语音记录只在内存里**：进程中途退出，这一场就没了（只在正常离场时落盘）。
- **跟随 DSH 进程**：关掉 DSH 就停止守候，插件不常驻后台。
- **B站 不允许给自己发私信**：高分推送要填另一个账号的 UID，留空则分数只写进笔记。

## 目录结构

```
index.js            宿主端：轮询开播、进退房间、读弹幕、触发回复、算分、写笔记（含 /api/bili-live/* 路由）
client.js           浏览器端：设置页那一页（自注册模块）
lib/live.mjs        与 B站 直播接口打交道（房间信息 / 弹幕长连接 / 发弹幕 / 拉流地址 / 随机房间）
lib/audio.mjs       音频拉流与切片（FLV 增量解析，只留音频 tag）
lib/asr.mjs         常驻转写进程的宿主侧封装（faster-whisper）
lib/vision.mjs      画面抽样（FLV 切片 → 抽帧）
lib/rating.mjs      八维评分：采集、归一、加权
lib/recap.mjs       直播记录器 + txt 笔记落盘
lib/auth.mjs        扫码登录
lib/llm.mjs         借宿主 llm 服务生成回复与总结（失败静默降级）
lib/config.mjs      配置默认值与归一化
lib/cleanup.mjs     离场清理（切片、截图）
tools/asr_worker.py 转写工作进程（stdin/stdout 一行一条 JSON）
tools/grab_frame.py 抽帧进程（stdin 送 FLV，stdout 回 JPEG）
vendor/qrcode.js    二维码生成（MIT，qrcode-generator 1.4.4）
cordis.patch.yml    告诉 DSH：这个插件要跑起来
```
